# Ghost AI by Brendigo — code, security and release audit (22 November 2026)

## Review scope and method

The PR #40 audit pipeline scans first-party frontend TypeScript/React sources,
desktop Tauri/Rust sources, shared Rust AI agent sources, Python packaging and
maintenance scripts, and GitHub Actions workflow text.

- `scripts/ghost-ai-code-audit.py` inventories code boundaries for HTML insertion,
  evaluation, shell execution, external HTTP, unsafe Rust, TLS bypass and potential
  embedded credentials. It reports source path and line only, not secret values.
- `scripts/ghost-ai-dead-code-audit.py` produces conservative TypeScript import
  reachability and Rust module reachability inventories. Dynamic registration and
  compile-time macros can cause false positives; **no source files are auto-deleted**.
- `tests/test_ghost_ai_security_gates.py` asserts production CSP restrictions,
  Tauri window permission boundaries, debug-only UI automation, signed-updater
  configuration checks and cross-platform release requirements.
- Quality Gates separately run `pnpm build`, frontend tests, Python tests, Windows
  Rust library tests and startup/screenshot checks, `pnpm audit` and RustSec
  `cargo audit` for both workspace lockfiles.

The generated `Ghost-AI-Code-Review` artifact contains full source review
inventories. **Static inventory is not a complete manual security audit** and
does not prove absence of unreferenced runtime code or vulnerabilities.

## Release matrix and publication rules

| Platform | Installer | Portable | How verified |
|---|---|---|---|
| Windows | Setup.exe, Update.exe | Portable.exe and Portable.zip | Real startup, installer, portable, update and SHA-256 checks |
| Linux | Linux.deb | Linux.AppImage | Build and package presence; real-world clean-machine startup remains to be checked |
| macOS | macOS.dmg | macOS-Portable.zip with .app | Build, bundle metadata and ZIP integrity; signing/notarization depends on credentials |

The release workflow rejects missing assets and never publishes when any
required OS job fails. macOS signing/notarization and Windows Authenticode are
not certified merely by the build passing.

## Outstanding functionality and security verification

- Exercise providers (hosted and local), tool approvals, MCP connections,

  import/export and all Settings screens on actual supported hardware.

- Inspect screenshot artifacts at required window sizes and compare against
  approved visual references; captures alone do not prove pixel-perfect UI.
